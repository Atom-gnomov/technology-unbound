=== РЕНДЕР / ТЕХНИКА (1.12.2) ===
1. TransformType: TEISR не знает контекст — обернуть baked model в делегат с override handlePerspective(TransformType), писать тип в static поле перед вызовом TEISR. Анимации (отдача, серпентин, шомпол) применять ТОЛЬКО при FIRST_PERSON_*/THIRD_PERSON_*; fullbright glow и мерцание фитиля — во всех контекстах.
2. Никакого lastShot в NBT: отдача и падение серпентина едут от player.getCooldownTracker().getCooldown(item, partialTicks) — при выстреле ставим setCooldown(item, 12) (кулдаун нашего предмета задаём сами, «длинные» 12 тиков канона сохранены). Кулдаун синхронизирован клиенту, кривая 1→0 без байта NBT.
3. Окно перезарядки — клиентский static WeakHashMap<EntityPlayer,Long> reloadStart, заполняется в reload() на isRemote-ветке (40 тиков).
4. Обязательно override Item#shouldCauseReequipAnimation → return slotChanged (иначе смена NBT даёт ванильный re-equip bounce поверх отдачи).
5. Fullbright: chamberGlow и matchTip рендерятся отдельными проходами с lightmap 240/240 + GlStateManager.color; ПОСЛЕ каждого — сброс color(1,1,1,1) и восстановление lightmap (иначе окрасится следующая группа). Глинта у builtin/entity моделей в 1.12.2 нет вообще (renderEffect только для baked) — фиксируем честно: «зачарованная крафтовая аркебуза глинт не показывает»; при желании — ручной второй проход с RES_ITEM_GLINT, но в объём этой задачи не входит.
6. Мерцание фитиля: Minecraft.getMinecraft().world может быть null — null-check с fallback на System-время или статичную яркость.
7. UV: формулы развёртки w=2·(len+depth), h=depth+height (ствол 34×4×4 → 76×8, а не 76×16). Сумма всех 35 боксов ≈ 5.6k px² из 8.2k у атласа 128×64 — паковать скриптом, стартовать со 128×64; при нехватке 128×128 с обязательной правкой textureWidth/textureHeight.

=== АНИМАЦИИ ===
- Отдача (вся модель, до рендера, только в руках): cd = getCooldown(...) ∈ 1→0 за 12 тиков; recoil = cd²; translate назад по стволу 0.12·recoil блока + rotate задирание ствола до 12°·recoil.
- Серпентин: падение на полку за первые 3 тика после выстрела: s = clamp((1−cd)·4, 0, 1); rotateAngleZ = −0.9·(1−s). Перезарядка (reloadStart, 40 тиков): последние 8 тиков плавный взвод обратно к −0.9. Вне циклов: взведён, если заряжена; лежит на полке, если пуста.
- Шомпол: p = (t − reloadStart)/40; при p∈[0.2,0.8] offsetX = −8·sin(π·(p−0.2)/0.6)/32 — ход СОКРАЩЁН до 8 юнитов: задний конец остаётся в задней трубке, движение читается как «дёрнул шомпол». В текстовке зафиксировано: стержень скользит под стволом, в канал не входит — осознанное упрощение школы Флана. Группа без вращений.
- Мерцание уголька: color(1, 0.6+0.15·sin(time·0.3), 0.2±...) — колебание яркости того же оранжевого, эмиссив-бюджет не растёт; time с null-check мира.
- Дым и искры при выстреле — партиклы (SMOKE_LARGE + FLAME) из точки ПОЛКИ (глобально ~(-0.5, 0, 4)·1/32 от origin модели), не геометрия.

- Уголёк тлеет всегда в руках (matchTip fullbright) — «пилотный огонёк», виден ночью.

- БЛОКЕР (оба критика): 45°-child казённика удалён полностью — ребро звезды на радиусе 4.24 прошивало обе glow-щели и хоронило целик, заявление «прикрыто собственным сечением» математически ложно; казённик гладкий 10,6,6, щели на чистых гранях, −1 бокс и −~336 px² UV
- БЛОКЕР (оба критика): сквозная дыра x∈[-4..6] закрыта замочной колодкой великодрева addBox(-4,-5,-2.5,10,7,5); замочная доска прижата к ней (z 2.5..3.5), пивот серпентина (3,-1,3.5), z-глубины замка сдвинуты на -0.5; дужка скобы удлинена до 1,4,2, чтобы дорасти до низа колодки — ни один бокс не висит в воздухе
- Штык (критик 1, суть принята): узел крепления заложен в геометрию сейчас — латунный хомут addBox(-45,-3.5,-3.5,2,7,7) на стволе; сам клинок — по канону (см. rejected)
- Мушка (критик 1): посажена поверх крыши надульника addBox(-49,3,-0.5,2,3,1) — 3 юнита силуэтного зубца вместо утопленного 1
- Тёмное-на-тёмном (критик 1): самозапрет на #5A3A22 снят, великодрево полной рампой до #7A5733 на освещённых гранях; контраст-скрин с 10 блоков до финализации текстуры
- Серпентин удлинён (критик 1): нижнее плечо 2,7,1, верхнее на local y 6..8 — взведённый фитиль на 7–8 юнитов над линией ствола, уголёк-эмиссив виден в профиль
- Полка под фитиль (критик 2): полка сдвинута назад — кончик при угле 0 ложится ровно над ней, партиклы бьют из полки
- NBT-рассинхрон и re-equip bounce (критик 2): отдача и серпентин от getCooldownTracker().getCooldown() вместо NBT-времени; reloadStart — клиентский WeakHashMap; обязателен override shouldCauseReequipAnimation → slotChanged
- TransformType (критик 2): делегат с handlePerspective + static поле; анимации только в FIRST/THIRD_PERSON, glow и мерцание — везде
- Display-числа (критик 2 + yaw критика 1): firstperson ~0.22–0.25 с yaw 106–110°, gui ~0.30 с диагональю, ground ~0.25, fixed ~0.45; чек-лист FOV 90+ и приседание
- Кольца (оба критика): addBox(...,-3.5, 2,9,7) — симметрия по z, накрыты ребро 2.83 и цевьё 3.0, размеры целые
- Честное имя профиля (критик 2): звёздчатый/фасонный, не октагон; реальный зазор 0.01 у торца child (x от -46.99)
- Glow-щели увеличены (критик 1): верхняя 6,1,3, боковая 5,3,1 — пять цветов патронов различимы в third person, крупнее нельзя

- Кончик фитиля — отдельный ModelRenderer с fullbright-проходом (критик 1): «пилотный огонёк» честно виден ночью
- Шомпол: ход сокращён до 8 юнитов (критик 1, вариант А) — задний конец остаётся в трубке; текстовка «стержень скользит под стволом, в канал не входит» (критик 2)
- Глинт (критик 2): риск «окрашенного глинта» вычеркнут как пустой — builtin/entity глинт не рисует; зафиксировано «зачарованная крафтовая глинт не показывает», сброс color/lightmap всё равно обязателен

- Null-check мира для мерцания фитиля (критик 2)

## Отклонённая критика (с обоснованием)

- Критик 1, штык как собственные 4-6 боксов «клинок+кольцо» — ОТКЛОНЕНО по канону: bayonet_arquebus.md §8 прямо велит рендерить модель ВЛОЖЕННОГО меча из NBT («видно, какой именно меч приделан; игрок узнаёт чужой клинок мгновенно», рендер предмета в предмете как у витрин ТК). Обобщённый боксовый клинок это ломает. Принята только часть про узел крепления: латунный хомут заложен в геометрию и UV сейчас.
- Критик 2, мушка addBox(-48.5,2.9,...) на ребре звезды — ОТКЛОНЕНО в пользу посадки на крышу надульника (фикс критика 1): база на наклонном ребре 2.83 касается металла по линии, рост остаётся 2 юнита и зубец по-прежнему не читается; на плоской латуни база честная и рост 3 юнита.
