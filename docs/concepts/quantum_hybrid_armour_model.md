## Итоговое ТЗ

ИТОГОВОЕ ТЗ: quantum_hybrid_armour (все правки критиков внесены; блокеры закрыты)

=== СИЛУЭТ ===
С 10 блоков читается «библиарий в силовой броне»: массивный квант-корпус с гребнем-короной над головой (крест из 4 пластин + продольный капюшон-гребень, голова на 3 юнита выше ванильной), двухъярусные наплечники шире торса более чем на юнит с каждой стороны, и вертикальная светящаяся ось — самоцвет лба → амулет груди → шкала из 4 ламп у оси → кристаллы наручей. Путь опознаётся по второму признаку: у Пустотного (А) за спиной качается рваный плащ, свечение холодное лилово-голубое и ТОЛЬКО на оси (пластины — матовая тьма, не светятся, пока их не пробили); у Ихорного (Б) плаща нет, но швы и жерла пульсируют тёплым золотом, которое никогда не гаснет. Ноги — ступенчатая пирамида нано-школы: штанина → бот → сабатон с соплами, низ тяжелее верха.

=== КОНВЕНЦИИ (обязательные) ===
1. Класс ModelQuantumHybridArmour extends ModelBiped (канон §8, фортресс-наследование запрещено). Боксы в обычных бипед-юнитах, размеры ТОЛЬКО целые; полутона — дробными offset/infl.
2. ОСИ И ИМЕНА: +X = ЛЕВАЯ сторона персонажа (bipedLeftArm на +5). Суффикс L = деталь на +X, R = на -X. Техническая сторона тела — ЛЕВАЯ: разъём, жгут, гримуар. Словесные описания сторон вторичны, числа первичны.
3. ПИВОТЫ: каждая деталь с ненулевым rotate* получает СВОЙ setRotationPoint у своего основания, box задаётся относительно этого пивота. Запрещено вращать детали вокруг дефолтного (0,0,0) кости.
4. Текстура: textureWidth=128, textureHeight=64 (юниты модели); PNG-файлы 256x128 px (2 px/юнит). Файлы: quant_void.png / quant_ichor.png + покадровые эмиссивы quant_void_glow_0..7.png / quant_ichor_glow_0..7.png. Генерит tools/gen_quantum_hybrid.py из реальных quantum_1/quantum_2 IC2. Зеркальные детали шарят UV через mirror=true (как suitArmL у нано). ОБЯЗАТЕЛЬНО: таблица UV-дыр до кода; мелочь (лампы, кристаллы) паковать в правый край плоскости (юниты 100..127).
5. Толстая модель scale=1.0 (шлем/грудь/боты), тонкая 0.5 (поножи); детали строго за раздутой поверхностью.
6. ItemStack нагрудника пробрасывается в модель из getArmorModel (Forge вызывает каждый кадр): path (метадата), charge (NBT), lastAbsorbTime, breachTime. Никакого кэша в полях модели — флаги ставятся каждый кадр.
7. Эмиссив: второй проход ВНУТРИ render() модели — после базового прохода bindTexture(glow-кадр по worldTime), сохранить OpenGlHelper.lastBrightnessX/Y, setLightmapTextureCoords(240,240), disableLighting, отрендерить только glow-детали по showModel-маске, восстановить состояние. Никаких своих LayerBipedArmor и RenderPlayer-хуков — работает на игроках (обе модели) и стендах автоматически.

## Принятая критика

- К1-1/К2-7 (блокер): плащ прошивает рёбра-радиаторы — capePivot перенесён на z=4.3 (за торец рёбер 4.15, зазор 0.15), рёбра не трогаем
- К1-2 (блокер): гримуар внутри объёма руки — книга перенесена на внешнюю грань левого бедра (bipedLeftLeg, LEGS-слот), по варианту Б первого критика; с рукавом 0.4 клиренс сходится
- К1-3 (блокер): эмиссив-швы пути А убивали заявку «поглощает свет» и стирали различие путей — статичный эмиссив пути А оставлен ТОЛЬКО на вертикальной оси (самоцвет, амулет, лампы, кристаллы) + щели паулдронов; швы тёмные и вспыхивают лишь в 10-тиковой вспышке пробоя
- К2-1 (блокер): mcmeta не работает на броневых текстурах (SimpleTexture, не атлас) — все анимации переведены на покадровые glow-PNG с биндом по worldTime; слово mcmeta изъято из концепта
